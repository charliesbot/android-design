# Repository Purpose

Home of the `android-design` and `android-design-explore` agent skills (Material 3 Expressive design judgment for Jetpack Compose and live exploration in the native previewer), plus the distilled research and evals behind them.

**Scope:** Phone, foldable, tablet, desktop, and Wear OS app screens are validated (with Wear eval cases). Wear tiles, watch faces, and home widgets are out of scope (widen skill descriptions only once eval cases and a passing widget catalog exist). AI glasses, cars, TV, and XR are also out of scope, skipped in `docs/research/source-coverage.md`, and never fetched.

## Repository conventions

- **Release tagging:** Changing `version` in `plugin/plugin.json` on `main` triggers `.github/workflows/release-previewer.yml` to verify manifests and create the `v<version>` tag. Bump versions only when asked for a release, and keep all manifests, `plugin/skills/android-design-explore/scripts/android-design-preview`, and `AppInfo.VERSION` in `Main.kt` synced (`scripts/test_plugin_manifests.py`).
- **Skill distribution:** Chai and `npx skills` install directly from `plugin/skills/`, so keep non-skill files out of those folders. The `android-design-preview` POSIX bootstrap script lives inside `plugin/skills/android-design-explore/scripts/` so every install route ships it (macOS and Linux only; Windows is unsupported).
- **Upstream sources:** `sources/` is generated by `scripts/fetch.py`; never edit it by hand. For source-distillation rules and upstream sync steps, read [docs/research/upstream-sync.md](docs/research/upstream-sync.md).
- **Docs and tracking:** `docs/design/` holds focused design docs in lowercase kebab-case; `docs/archive/` holds superseded history. Track approved delivery work in GitHub issues at https://github.com/charliesbot/android-design.

## Deliberate decisions

Settled choices; do not flag them in reviews unless the reasoning no longer holds.

- **Typeface standard:** Plain text (Title Medium/Small, Body, Label) uses Google Sans Flex; Display, Headline, and Title Large allow at most one bundled brand face (Doto at Display only); numbers and data use Google Sans Code. Every face is bundled so explorations never fetch fonts. Defined in [plugin/skills/android-design/SKILL.md](plugin/skills/android-design/SKILL.md); this is the owner's rule, enforced by the eval rubric.
- **Rules from Google docs, not apps:** Shipped apps (including Google's) are examples. A pattern becomes a rule only when an official Google source in `sources/` states it.
- **Git is the source inventory:** `sources/` files carry no dates or hashes so unchanged pages diff clean.
- **Coverage check proves agreement, not freshness:** `scripts/check_coverage.py` verifies `docs/research/source-coverage.md` against `sources/`; only `scripts/fetch.py` checks upstream.

## Verification

| Change | Check |
| --- | --- |
| Either skill | Current harness only (`evals/README.md`): `evals/run.py prepare`, fresh current-harness subagents (default model), `evaluate`, and `score`. Never shell out to `agy`, `claude`, or `codex` unless explicitly requested. |
| Skill `description` | Trigger evals (`evals/README.md`, Trigger evals); `evals/trigger_eval.py` calls `claude -p`, so run only when explicitly evaluating Claude Code triggering. |
| Rubric (`evals/rubric.md`) | `evals/calibrate.py prepare` and `score` with blind subagents in the current harness first; invoke `--judge` CLI automation only when explicitly requested. |
| `evals/` | `python3 -m unittest discover evals` |
| `scripts/`, bootstrap, `plugin/bin/`, manifests | `python3 -m unittest discover scripts` (also run `cd app && ./gradlew :host:exportBootstrap build spotlessCheck` for bootstrap, `plugin/bin/`, or manifests) |
| Previewer (`app/`) | `cd app && ./gradlew :host:exportBootstrap build spotlessCheck` |
| Pinned `material3` version (`app/gradle/libs.versions.toml`) | `python3 scripts/material3_inventory.py`, `python3 scripts/generate_signatures.py`, update `scripts/test_m3_page_coverage.py` and `CallNameMapper.kt` for new components, then `python3 -m unittest discover scripts` |
| `compose-signatures.md` or kit DSL | `python3 scripts/generate_signatures.py` and `python3 -m unittest discover scripts` |

## Prose

Write repository prose (`SKILL.md`, references, docs, `README.md`, and code comments; `sources/` is exempt) with commas, colons, periods, parentheses, or conjunctions instead of em-dashes.
