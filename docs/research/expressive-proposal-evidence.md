## Short source excerpts

1. **Content-color exception:** “Full-screen content-based color moments can orient users within a content-driven experience” ([advanced color, line 73](../../sources/m3.material.io/pages/styles/color/advanced.md#L73)). This proves an exception to universal neutral composition, not permission for arbitrary neon role mappings.
2. **Typography range:** “calm as a whisper” and “loud and rugged” ([Google Sans Flex, line 97](../../sources/design.google/library/google-sans-flex-font.md#L97)). Both belong to the stated expressive range.
3. **Role distinction:** “Always apply color roles rather than static values or tonal palette values” ([advanced color, line 117](../../sources/m3.material.io/pages/styles/color/advanced.md#L117)). Reference inputs and applied UI values must therefore be evaluated separately.

## Counterevidence and limits

- **Neutral backgrounds remain intentional guidance.** [Color roles, lines 154-159](../../sources/m3.material.io/pages/styles/color/roles.md#L154-L159) recommends surface roles for more neutral backgrounds. [Color system, line 340](../../sources/m3.material.io/pages/styles/color/system.md#L340) maps surface roles to the neutral palette. [Color roles, line 208](../../sources/m3.material.io/pages/styles/color/roles.md#L208) permits remapping neutral component defaults. The correct change is an exception-aware default, not abandoning neutral surfaces.
- **Content-color exceptions have conditions.** [Advanced color, lines 74-76](../../sources/m3.material.io/pages/styles/color/advanced.md#L74-L76) keeps source content visible, limits source types, and protects semantic colors. Lines 115-117 require suitable contrast, testing dynamic themes, and color roles. A bold screenshot alone proves none of these.
- **Emphasis remains deliberate.** [Typography, lines 247-282](../../sources/m3.material.io/pages/styles/typography.md#L247-L282) increases weight for emphasized styles and recommends them for selection, actions, and headlines. [Expressive tactics, lines 182-190](../../sources/m3.material.io/pages/building-with-m3-expressive.md#L182-L190) emphasizes meaningful hero interactions and limits hero moments. Broadening successful typography is not permission for uniformly unaccented screens.
- **Category colors need semantics and implementation evidence.** The saved static-color guidance explicitly discusses brand and semantic use, not a blanket exemption for arbitrary finance category constants. A particular generator call, disabled harmonization setting, and exact contrast compliance require code-level verification beyond these pages.
- **Named variant details remain an evidence gap.** Color-system prose mentions `neutral variant` among five tonal palettes at lines 307-322. That does not establish a `Neutral` scheme variant, variant selection guidance, API defaults, spec-version support, or equivalence between a scheme named `Expressive` and the M3 Expressive design evolution.

## Result

Proceed only with source-bounded proposals: conditional color-role flexibility, contextual typography, and distinguishing inputs from applied role values. Treat calibration changes as engineering inferences. Defer named variant guidance until implementation evidence is committed under an agreed source policy. No source-backed requirement discovered here mandates changing the owner's font choice.
