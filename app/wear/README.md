# Wear Compose on desktop

Why the port exists and how Wear fits the previewer: `docs/design/wear-os-previewer.md`.

`compose/` (`:wear:compose`) compiles Google's real `androidx.wear.compose` sources (foundation,
material-core, material3, navigation3) for Compose Multiplatform desktop, so the previewer draws Wear
proposals with the same components a watch runs. The version is in `compose/upstream/VERSION`.

The rest of the app needs only the upstream Wear Compose API plus one entry point:

```kotlin
@Composable
fun WearDevice(widthDp: Int, heightDp: Int, round: Boolean, content: @Composable () -> Unit)
```

`WearDevice` (`compose/src/host/`) provides the screen size and shape, clips to a circle when round,
draws on black. The mouse wheel and trackpad scroll lists as plain scrolling. Crown (rotary) input is not
available in the previewer, so rotary-only behavior (crown-driven Stepper and Slider values, rotary snap) is
not shown.

`dynamicWearColorScheme(systemColor)` (same `src/host/`) runs Wear's own `dynamicColorScheme(context)`, the
watch-face theming, on system colors the caller supplies by name (`SystemColorNames`), so the previewer
derives a scheme from a seed with Google's role mapping and not a copy. It works through the shims:
`Resources` returns the supplied colors, `ContentResolver` holds the `dynamic_color_theme_enabled` setting,
and `Build.VERSION.withSdk` raises `SDK_INT` to 35 on the calling thread for the length of that one call.

## Lazy lists and the layout tree

A scrolling Wear screen is a `TransformingLazyColumn`, which composes only the items on screen. The layout
tree (`get_tree`) and its findings (`check_proposal`, `render`) therefore cover only the items visible at
the current scroll, which for a fresh render is the top of the list; items below, and an edge button that
only appears at the end of a long list, are not checked. Scroll the window (mouse wheel) to look further. `round-edge-clipped` skips every node under a
scrolling `Screen` (`docs/design/wear-os-previewer.md`).

## Rule: upstream stays byte-identical

`compose/upstream/` is Google's source, byte for byte (META-INF dropped). Make
it compile by adding a shim in `compose/src/shims/kotlin/` (same package as what upstream imports) or
by excluding a file in `compose/build.gradle.kts`. `scripts/sync_wear_compose.py` replaces the
directory wholesale, so a hand edit to upstream would vanish on the next sync.

## Source layout

- `upstream/{foundation,material-core,material3,navigation3}`: Google's sources.
- `src/shims/kotlin`: hand-written stand-ins (below).
- `src/generated/kotlin/.../material3/R.kt`: generated by the sync script from the aar's
  `res/values/values.xml` and `res/drawable/` (English strings, plurals, drawable ids).
- `src/host/kotlin`: `WearDevice` and `dynamicWearColorScheme`.
- `src/main/resources/fonts`: Roboto Flex (variable, from github.com/google/fonts `ofl/robotoflex`)
  and its OFL license.
- `src/test/kotlin/wear`: `SpikeScreen` fixture and headless render tests. They write PNGs to
  `compose/build/renders/`.

## Shims

Android framework stubs, in the packages upstream imports: `android.R` (system color ids and
`style.Animation`), `annotation.SuppressLint`, `content.Context` (+ ContentResolver, Intent,
IntentFilter, BroadcastReceiver; no services), `content.pm.PackageManager`,
`content.res.Configuration` and `Resources`, `database.ContentObserver`, `net.Uri`, `os` (Build,
Looper, Handler, Bundle), `provider.Settings` (every setting reads its default), `text.format.DateFormat`
(24 h), `util.Log`, `view` (View, ViewGroup, Window, insets, ViewConfiguration, MotionEvent,
InputDevice, Surface: all inert), `view.accessibility.AccessibilityManager` (touch exploration off).

androidx stubs: `core.os.HandlerCompat`, `core.util.Predicate`, `core.content.ContextCompat`,
`wear.utils.WearApiVersionHelper` (every version check false), `graphics.shapes.ToPath`
(`Morph.toPath(progress)` for AnimatedCornerShape).

Compose APIs missing on desktop: `LocalContext`, `LocalConfiguration`, `LocalView`,
`AndroidUiDispatcher`, `stringResource` and `pluralStringResource` over the generated English map,
`ImageVector.vectorResource` and `AnimatedImageVector` (see Dialogs), `PlatformTextStyle(includeFontPadding)`,
`Font(DeviceFontFamilyName, ...)` (see Typography), `Modifier.systemGestureExclusion`,
`WindowInsets.statusBarsIgnoringVisibility`, and for dialogs `DialogWindowProvider`,
`SecureFlagPolicy` and the Android `DialogProperties(...)` factory.

Wear-specific: `AndroidInputCompat` (`Any.device`), `rotary/RotaryEventCompat`
(`RotaryScrollEvent.inputDeviceId`), `ExcludedColors` (empty classes ColorScheme names),
`DialogPropertiesCompat`, `WearDrawables`, and the Wear SDK stubs `com.google.wear.{Sdk,input.GestureInput,settings.WearSettings}`
(no feature present).

Desktop replacements for excluded upstream files (same API, different tail): `BasicCurvedTextDesktop`,
`LocalAmbientModeManagerDesktop` (always Interactive), `RotaryHapticsDesktop` (no-op haptics).

Trick: same-package extension members let upstream call Android-only members on desktop types without
edits (`Any.device`, `RotaryScrollEvent.inputDeviceId`, `DialogProperties.securePolicy`), and a same-named
top-level function adds Android-only constructor overloads (`PlatformTextStyle`, `DialogProperties`).

## Excluded upstream files (10)

Replaced by a desktop shim (4):
- `foundation/BasicCurvedText.kt`: draws with `android.graphics.TextPaint`.
- `foundation/WarpedCurvedTextRenderer.kt`: `android.graphics` path warping. Dropped, no replacement.
- `foundation/LocalAmbientModeManager.kt`: needs the com.google.wear ambient SDK and an Activity.
- `foundation/rotary/Haptics.kt`: Android haptic constants and ScrollFeedbackProvider.

Not needed or not portable (6):
- `R.java`: empty aapt output, replaced by the generated `R.kt`.
- `OpenOnPhoneDialog.kt`: animated vector with many animators.
- `DatePicker.kt`, `TimePicker.kt`: `Configuration.locales`, `DateFormat` order, API 26 gates.
- `AnimatedText.kt`: `android.graphics.fonts` and `TextRunShaper` font-axis animation.
- `CurveToEdge.kt`: AGSL `RuntimeShader` and `RenderEffect`.

`ColorScheme.kt` names the colors classes of the excluded files, hence `ExcludedColors.kt`.

## Typography

Wear tokens ask for `Font(DeviceFontFamilyName("roboto-flex"), weight, variationSettings)`. The shim
clones the bundled Roboto Flex with the requested `wght` and `wdth` (explicit variation settings win
over the plain weight). `DeviceFontTest` checks both axes change the glyphs and that a bold
`FontWeight` does not embolden the variable font a second time.

## Dialogs

`AlertDialog`, `ConfirmationDialog` and `Dialog.kt` are upstream. The Android window is faked
(`DialogWindowProvider`, a no-op `Window`). Animated vector XML cannot load on desktop, so
`WearDrawables` rebuilds the check and failure animations by hand from the XML path data and replays
their stroke-trim animation; the error icon is a static vector.

On desktop a dialog is a layer over the whole Compose scene, not over `WearDevice`. Size the scene to
the device when a dialog may show.

## Known fidelity gaps

- Curved text has no kerning and no glyph warping: glyphs sit on the arc with plain advances, slightly
  flatter and wider than on a watch.
- `Build.VERSION.SDK_INT` is 30 on purpose, so every API-gated upstream branch stays off.
- Strings are English only. Settings, accessibility, ambient mode, the status bar and one-handed gestures are inert.
- No haptics.
- No pickers, `OpenOnPhoneDialog`, `AnimatedText` or `curveToEdge`.

## Upgrading

1. Check version alignment. Read the new version's `.module` files on Google Maven
   (`https://dl.google.com/android/maven2/androidx/wear/compose/<artifact>/<version>/<artifact>-<version>.module`).
   Its Jetpack Compose requirements (`foundation`, `ui`, `runtime`, `animation`) must be no newer than what the
   app's Compose Multiplatform provides, and its `navigation3` requirement no newer than `navigation3` in
   `app/gradle/libs.versions.toml`. If either is newer, upgrade Compose Multiplatform first.
2. `python3 scripts/sync_wear_compose.py <version>` (about 10 s; downloads the four `-sources.jar` files and the material3 `.aar` from Google Maven).
3. `cd app && ./gradlew build spotlessCheck`.
4. Fix compile errors with shims or exclusions, and record each new one in this README.
5. Set the new version in `WearExporter.WEAR_COMPOSE_VERSION` (`core/domain/.../export/wear/`, named in the exported Kotlin's header) and in `evals/wear-starter/gradle/libs.versions.toml`, then check the exporter's calls against the new API with the Wear export check (`evals/README.md`).
6. Look at `compose/build/renders/*.png` and at a Wear fixture rendered with the CLI.
